## Recording a completed case

For each case, record the exact scenario and scope, source/build identifier, environment/schema/provider contract versions, test command or reviewed procedure, result, protected artifact references/hashes, unresolved limitations, and reviewer/date where required. Include intentional rejection cases. Distinguish a passing automated check from live finance acceptance.

T37 adds application SQL cases incrementally after T08, then with T09/T11/T14/T16/T19/T23/T25/T28–T30/T34. T36 adds rendered-browser evidence; T39 adds restore/migration evidence; T40 adds capacity measurements; T41 collects final acceptance. This tracker is an implementation and evidence checklist, not a claim that its planned checks have run.

Release requires all applicable cases to meet their full criteria and the draft's required live signoffs. Any waiver must explicitly change the accepted release scope with a named owner and rationale; neither a fixture pass nor a Pending label waives a requirement.
